# 《弦枰墨境》寻宝首页实现规格说明

## 一、文档目的

本文档以提供的首页示意图为目标，拆解《弦枰墨境》首页在网页端的结构、视觉样式、素材需求、内容组织、后端处理逻辑、前端动效和后续资源准备方案。

目标技术栈为：

- 前端：HTML5、CSS3、JavaScript，可配合 Bootstrap 或原生 CSS 响应式布局
- 后端：Django
- 数据库：MySQL 或 SQLite
- 模板：Django Templates
- 图片格式：WebP 优先，PNG 适合透明素材，JPG 适合大背景
- 音频格式：MP3 或 OGG

这张示意图应作为“视觉目标”和“布局参考”，不建议直接把整张图作为网页背景。实际开发时应将其拆分为背景、面板、图标、卡片、地图、人物和动效素材，使内容可以由 Django 数据动态更新。

---

## 二、目标页面基本信息

### 2.1 页面类型

桌面端寻宝型国风文化网站首页，兼具以下功能：

1. 用户登录状态展示
2. 每日寻宝线索展示
3. 任务完成与进度记录
4. 琴棋书画四类文化探索
5. 宝物和线索收集
6. 积分与成就统计
7. 小游戏入口
8. 点亮古画入口
9. 人物装扮入口
10. 收藏和个人成长数据展示

### 2.2 建议设计尺寸

示意图比例约为 16:9，可按以下尺寸设计：

| 项目 | 建议值 |
|---|---:|
| 设计稿尺寸 | 1600 × 900 px |
| 最小桌面宽度 | 1200 px |
| 推荐开发基准 | 1440 × 900 px |
| 内容最大宽度 | 1440—1520 px |
| 页面左右安全边距 | 24—48 px |
| 顶部导航高度 | 64—72 px |
| 桌面端主体高度 | 828—836 px |
| 页面圆角 | 8—18 px |
| 普通正文大小 | 14—16 px |
| 模块标题大小 | 20—28 px |
| 主标题大小 | 30—48 px |

### 2.3 设计原则

- 页面重点必须是“探索”和“寻宝”，不是普通展览网站。
- 页面内容建议拆成独立模块，便于后期接入 Django 数据。
- 背景可以保持浓郁国风，但按钮、进度条和状态信息必须清楚易读。
- 首页不宜堆积过多动态效果，首屏以快速加载和明确交互为主。
- 所有任务、积分、收藏和成就数字都应由后端返回，不使用固定写死的数据。

## 五、视觉样式规范

### 5.1 配色方案

| 用途 | 色值 | 说明 |
|---|---|---|
| 页面主背景 | `#171412` | 深色木桌和暗色空间 |
| 深色面板 | `#211A16` | 导航、档案、底部功能区 |
| 纸张背景 | `#E6D4B8` | 线索、日志、任务面板 |
| 旧纸高光 | `#F1E5CD` | 卡片内部浅色区域 |
| 墨黑文字 | `#241C17` | 主要正文和标题 |
| 金色强调 | `#C59A55` | 进度、边框、宝箱、图标 |
| 朱砂色 | `#9E3F32` | 激活、按钮、印章、错误状态 |
| 青绿色 | `#4B776C` | 完成状态、探索成功、正向提示 |
| 辅助灰棕 | `#8B7660` | 次级文字和未激活状态 |

### 5.2 字体

建议字体优先级：

```css
font-family: "Noto Serif SC", "Source Han Serif SC", "Songti SC", serif;
```

正文使用易读的宋体或思源宋体，标题可使用具有书法感的字体，但不能全部使用书法字体。建议：

- 网站Logo：书法字体或手写字体
- 模块标题：宋体加粗或较稳重的明朝体
- 正文：宋体、思源宋体
- 数字：衬线字体或清晰的数字字体
- 小按钮：黑体或无衬线字体

### 5.3 边框和材质

- 面板边框：1 px 半透明金色或棕色
- 纸张边缘：使用不规则边缘图片或 CSS `clip-path`
- 阴影：深色柔和阴影，避免现代卡片式大阴影
- 纹理：纸张、旧木、丝绸、铜器、墨迹
- 印章：朱红色小印章作为标题装饰，不宜每个元素都使用
- 纹理透明度：通常控制在 10%—25%

### 5.4 圆角和动效形态

国风寻宝界面不建议所有组件使用大圆角。建议：

- 纸张面板：2—8 px
- 功能卡片：6—12 px
- 圆形图标：50%
- 宝箱按钮：4—8 px
- 罗盘和玉佩：使用真实形状图片，不强行圆角

## 八、Django 后端数据模型

首页需要动态显示任务、用户数据、线索和宝物，因此建议设计以下模型。

### 8.1 用户模型 UserProfile

```python
class UserProfile(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE)
    nickname = models.CharField(max_length=50)
    avatar = models.ImageField(upload_to='avatars/', blank=True, null=True)
    level = models.CharField(max_length=30, default='初入艺境')
    points = models.IntegerField(default=0)
    exploration_progress = models.PositiveIntegerField(default=0)
    created_at = models.DateTimeField(auto_now_add=True)
```

### 8.2 每日任务 DailyTask

```python
class DailyTask(models.Model):
    title = models.CharField(max_length=100)
    description = models.TextField(blank=True)
    task_type = models.CharField(max_length=30)
    reward_points = models.PositiveIntegerField(default=10)
    target_count = models.PositiveIntegerField(default=1)
    is_active = models.BooleanField(default=True)
```

### 8.3 用户任务 UserTask

```python
class UserTask(models.Model):
    user = models.ForeignKey(User, on_delete=models.CASCADE)
    task = models.ForeignKey(DailyTask, on_delete=models.CASCADE)
    progress = models.PositiveIntegerField(default=0)
    is_completed = models.BooleanField(default=False)
    is_reward_claimed = models.BooleanField(default=False)
    task_date = models.DateField()
    completed_at = models.DateTimeField(blank=True, null=True)
```

### 8.4 寻宝线索 Clue

## 九、首页后端处理逻辑

### 9.1 首页访问流程

```text
用户访问首页
    ↓
判断是否登录
    ├── 未登录：显示默认头像、公共线索、登录入口
    └── 已登录：查询用户资料、任务、积分、成就、收藏和宝物
    ↓
生成或读取当天任务
    ↓
计算任务完成数量和探索进度
    ↓
查询今日推荐线索
    ↓
查询用户已解锁宝物和功能入口
    ↓
渲染 Django 首页模板
```

### 9.2 首页 View 示例逻辑

```python
def home(request):
    user = request.user
    today = timezone.localdate()

    daily_tasks = get_or_create_today_tasks(user, today)
    task_completed = daily_tasks.filter(is_completed=True).count()
    task_total = daily_tasks.count()

    profile = get_user_profile(user)
    current_clue = get_today_clue(user)
    recent_clues = get_recent_clues(user, limit=3)
    achievements = get_user_achievements(user)
    treasures = get_user_treasures(user)

    context = {
        'profile': profile,
        'daily_tasks': daily_tasks,
        'task_completed': task_completed,
        'task_total': task_total,
        'current_clue': current_clue,
        'recent_clues': recent_clues,
        'achievements': achievements,
        'treasures': treasures,
    }
    return render(request, 'home/index.html', context)
```

### 9.3 每日任务生成逻辑

1. 用户当天第一次进入首页。
2. 查询是否已经生成当天任务。
3. 如果没有，从启用任务池中随机抽取 3—5 条。
4. 创建 `UserTask` 记录。
5. 首页显示这些任务。
6. 用户完成浏览、答题、游戏或收藏行为后更新进度。
7. 任务达成后显示“领取奖励”。
8. 用户领取奖励时开启数据库事务，增加积分并标记已领取。

必须防止重复领取奖励：

```python
@transaction.atomic
def claim_task_reward(user, user_task_id):
    user_task = UserTask.objects.select_for_update().get(
        id=user_task_id,
        user=user,
        is_completed=True,
        is_reward_claimed=False,
    )
    user.profile.points += user_task.task.reward_points
    user.profile.save(update_fields=['points'])
    user_task.is_reward_claimed = True
    user_task.save(update_fields=['is_reward_claimed'])
```

### 9.4 线索解锁逻辑

1. 用户点击“查看线索”。
2. 后端判断用户是否已经解锁。
3. 未解锁时检查前置任务或前置线索。
4. 条件满足后创建 `UserClue`。
5. 返回线索详情、奖励积分和下一步提示。
6. 首页地图节点由锁定状态变为激活状态。

### 9.5 探索进度计算

可以使用简单公式：

```text
探索进度 = 已完成任务、已收集线索、已解锁宝物的加权总和 / 总目标数量
```

本科项目中可以采用更容易维护的方式：

```python
progress = round(
    (completed_clues + unlocked_treasures * 2 + completed_achievements)
    / total_progress_items * 100
)
```

进度结果限制在 0—100 之间，避免因数据异常超过 100%。

### 9.6 游戏奖励逻辑

小游戏完成后提交：

```text
game_type
score
completion_time
user_id
```

后端校验：

- 用户是否登录
- 分数是否超过合理上限
- 是否在短时间内重复提交
- 是否已经领取过本次奖励

校验通过后：

1. 写入 `GameRecord`。
2. 增加用户积分。
3. 更新对应任务进度。
4. 检查是否解锁成就。
5. 返回积分、成就和动画提示所需数据。

## 十、建议的接口设计

如果使用 Django 原生视图，可以采用普通 POST 表单；如果希望交互更流畅，可使用 JSON 接口。

| 接口 | 方法 | 作用 |
|---|---|---|
| `/` | GET | 首页数据 |
| `/api/tasks/today/` | GET | 获取今日任务 |
| `/api/tasks/<id>/claim/` | POST | 领取任务奖励 |

## 十一、前端动效规划

### 11.1 页面首次进入

动效顺序建议：

1. 背景从暗到亮，持续 300—500 ms。
2. 顶部导航从上方淡入。
3. 左右侧面板从两侧轻微滑入。
4. 中央线索纸张从下方展开。
5. 地图路线逐段显示。
6. 宝箱出现一次轻微金色闪光。

不要让所有模块同时剧烈运动，避免影响阅读。

### 11.2 导航栏动效

- 当前导航下方出现朱砂色短线。
- 鼠标悬停时文字颜色变为金色。
- 图标轻微上移 2 px。
- 点击后显示 100—200 ms 的按压效果。

### 11.3 今日任务动效

- 任务完成时空心圆变为勾选圆。
- 进度条从旧值平滑增长到新值。
- 奖励可领取时显示金色呼吸光。
- 领取成功时弹出“获得 +10 积分”。

### 11.4 中央线索面板动效

- 线索纸张展开：使用 `transform: scaleY()` 或 CSS 3D 翻页。
- 查看线索：正文逐行淡入。
- 新线索解锁：印章从上方落下并轻微缩放。
- 线索完成：纸张边缘出现短暂金色光线。

### 11.5 地图路线动效

- 未解锁路径：低透明度灰棕色虚线。
- 已解锁路径：朱砂色虚线。
- 当前路径：金色流光沿虚线移动。
- 宝箱节点：每 3—5 秒轻微缩放一次。
- 点击节点：地图卡片上浮，背景周围增加暗色遮罩。

### 11.6 宝箱开启动效


## 十九、结论

这张首页示意图最适合被实现为“寻宝任务控制台”，而不是一张静态文化展览首页。实现重点应放在：

1. 中央线索和地图形成探索主线。
2. 左侧任务和日志形成每日使用入口。
3. 右侧用户档案形成成长反馈。
4. 底部小游戏、点亮古画和人物换装形成扩展玩法。
5. Django负责用户、任务、线索、宝物、积分和成就的数据闭环。
6. 前端通过 CSS、JavaScript 和少量透明素材实现纸张展开、路线流光、宝箱开启和进度变化。

实际制作时，建议先完成静态首页和数据库模型，再接入任务与积分，最后制作点亮古画、宝箱和换装等特色动效。这样可以控制本科毕设的开发规模，同时保留足够的设计亮点。
